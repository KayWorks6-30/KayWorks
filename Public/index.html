How KayWorks apps work

Simple on purpose.

The technical choices are mostly there to remove friction, not to show off a stack.

01
○

No account by default

Many KayWorks apps do not need you to create an account just to remember who you are. If the app can do its job locally, that is usually the simpler answer.

02
⌂

Local-first

When appropriate, your application data stays in browser storage on your device instead of automatically being uploaded to a central KayWorks database.

03
⇄

Backups you control

Apps with meaningful history should support export and restore where practical. A JSON backup can preserve or move your information without requiring cloud sync.

04
◇

Privacy without magic claims

Local storage avoids creating an unnecessary shared database of everybody’s information. It does not make data invulnerable: browser data can be cleared, devices can be lost, and backups still matter.

05
✦

AI where it is actually useful

Some apps use Claude or another model to turn messy human input into structured information. AI is best treated as an interpretation layer. Important calculations and saved application behavior should stay deterministic where that makes sense.

06
</>

Browser software is enough surprisingly often

Most KayWorks projects are static HTML, CSS, and JavaScript that run in a normal browser and deploy cleanly to static hosting. A giant framework or backend only earns a place when the problem actually needs it.

open→do its job→remember locally→back up if you want→stay out of your way
problem→small app→less annoying
About

Just a dude who likes making useful things.

I’m a regular guy who likes building software in my free time. A lot of these apps start because I want something for myself, somebody in my family needs something, or an everyday task feels more annoying than it should be.

I like software that does its job without making you create another account, remember another password, or sign up for another monthly subscription. I’m also fine with keeping a small app small when that is all the problem needs.

KayWorks grew naturally out of those projects. It is the front door for the things that become useful enough to keep around and share.

No grand startup story. Mostly curiosity, practical problems, and a suspicious amount of time spent making rounded cards line up correctly.
Technical / architecture

Enough structure for the problem.

Money Tracker is the first mature example of the KayWorks approach. Smaller apps do not need to imitate its entire folder tree.

The boundary matters more than the buzzword.

As a project grows, UI, persistence, domain logic, parser/AI behavior, rules, tests, and release tooling should become easier to reason about independently. A tiny project can stay tiny. A larger one should gain structure when that structure pays for itself.

UI→domain / data interfaces
AI / parser→validation→deterministic behavior
application state→explicit persistence boundary
UIrendering · interactions
Domaincalculations · semantics
Parser / rulesinterpret · validate · normalize
Datastorage · schema · import/export
tests · docs · release tooling
Static by design

Vanilla browser technology and static hosting are a deliberate default, not something to apologize for.

Data stays separated

User data should not leak into public source, demo fixtures, screenshots, or repositories.

Environments can differ

Production, development, and demo builds can intentionally behave differently while sharing trusted core logic.

Deterministic core

Models can help interpret input. They should not quietly become the authoritative calculator for important application behavior.

Home Screen setup

Keep KayWorks one tap away.

iPhone / Safari

  1. Open kayworks.dev in Safari.
  2. Tap the Share button.
  3. Choose Add to Home Screen.
  4. Confirm the name “KayWorks” and tap Add.

Android / Chrome

  1. Open KayWorks in Chrome.
  2. Open the browser menu.
  3. Choose Install app or Add to Home screen.
  4. Confirm the prompt.
Storage reminder: KayWorks is only the launcher. Money Tracker, Ascend, and future apps live on separate origins and keep their own local storage. The hub does not combine or sync that data.
